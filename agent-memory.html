Lesson 1

Why AI Agents Need Memory

The Stateless Problem

  • Most agents work well within a single session but lose everything the moment it ends
  • No user preferences, no task history, no learned behavior persists
  • Every new session starts from scratch — a cognitive reset
  • Long-horizon tasks become impossible without continuity

The Memory-First Solution

  • Treat long-term memory as first-class infrastructure
  • Memory is external to the model, persistent, and structured
  • Agents that remember can personalize, adapt, and improve
  • Transforms stateless chatbots into intelligent assistants

"Memory engineering is to agents what database design is to applications — foundational infrastructure, not an afterthought."

Lesson 3

Building Persistent Memory Stores

Different memory types serve different purposes — a well-architected agent uses all three.

📚

Semantic Memory

Facts, knowledge, and domain information. "What does the agent know?"

Example: User preferences, product catalogs, company policies

📖

Episodic Memory

Past interactions, conversations, and events. "What has the agent experienced?"

Example: Previous conversations, task outcomes, user feedback

🛠️

Procedural Memory

Learned routines, workflows, and tool-use patterns. "What can the agent do?"

Example: Multi-step workflows, API call patterns, decision heuristics

Lesson 4

The Memory Manager

The Memory Manager orchestrates how your agent reads, writes, and retrieves memory during execution.

class MemoryManager: def __init__(self, db, embedder, llm): self.db = db # Oracle AI Database self.embedder = embedder # Embedding model self.llm = llm # LLM for summarization def read(self, query): # Semantic search over memory store return self.db.similarity_search( self.embedder.embed(query) ) def write(self, memory, mem_type): # Persist new memory with metadata self.db.store(memory, type=mem_type) def consolidate(self): # Compress & summarize older memories self.llm.summarize(self.db.get_stale())
Read

Fetch relevant context via semantic similarity search

Write

Consolidate

LLM-powered compression keeps memory lean and relevant

Lesson 6

Write-Back Loops: Self-Updating Memory

Agents don't just read memory — they autonomously update their own memory after each interaction.

1️⃣
Observe

Agent processes user input and generates a response

2️⃣
Extract

LLM identifies new facts, preferences, or outcomes worth remembering

3️⃣
Write

Memory Manager persists extracted knowledge to the Memory Core

4️⃣
Refine

Consolidation routine merges, compresses, and deduplicates

🔁
Key Insight:

Write-back loops create a virtuous cycle — each interaction makes the agent smarter, more personalized, and more effective for the next session.

Lesson 7

Assembling the Memory-Aware Agent

Put it all together: a fully stateful agent with startup routine, reasoning loop, and cross-session persistence.

① Startup Routine

Load prior context from the Memory Core. Restore user preferences, conversation history, and task state before generating any response.

② Recursive Reasoning Loop

At each turn: retrieve relevant memories → assemble context + tools → reason → act → extract new memories → write back.

③ Cross-Session Persistence

When the session ends, all learned knowledge persists in Oracle AI Database — ready for the next session instantaneously.

# The full agent lifecycle async def run_agent(user_input): # ① Startup: load prior context context = memory.read(user_input) tools = registry.search(user_input) # ② Reason & Act response = llm.invoke( input=user_input, context=context, tools=tools ) # ③ Write-back: persist new knowledge new_memories = llm.extract_facts( user_input, response ) memory.write(new_memories) return response

Key Takeaways & Design Principles

1
Memory Is Infrastructure

External, persistent, structured — not embedded in the context window.

2
Type Your Memories

Semantic, episodic, and procedural memories serve distinct roles in agent cognition.

3
Semantic Search Scales

Retrieve the right memories and tools at runtime — no prompt bloat.

4
Write-Back Creates Learning

Agents that update their own memory improve autonomously over time.

5
Startup Routines Matter

Load prior context before generating — continuity enables long-horizon tasks.

6
Consolidate Aggressively

Compress and deduplicate — unbounded memory growth degrades retrieval quality.
